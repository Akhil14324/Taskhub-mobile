# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

React (react-native-web via Expo) client for TaskHub (JavaScript + JSX; no TypeScript, linter or tests). The backend is a separate repo (`vgrand-taskhub-backend`, sibling folder, Node/Express + Postgres + Socket.IO); an API or socket contract change usually needs edits in both.

## Scope: website + PWA only

**There is no Android app and no iOS app, and none is planned.** The product is the website / installable PWA, nothing else. Expo is used only as the web bundler (Metro + `expo export -p web`).

- Do not build, fix, test or add anything for native: no `expo run:*`, `expo prebuild`, EAS builds/submits, `expo-dev-client` dev builds, Gradle/Xcode/fastlane, store submission, or native CI. The `android/`, `fastlane/`, `eas.json`, `google-services.json`, native CI workflow and `CI_BUILD_SETUP.md` were removed from this repo; don't recreate them.
- Verify against web only. When a task would touch native-only behaviour (Expo push, `expo-secure-store`, haptics, native permissions in `app.json`), ignore the native side and make the web path correct.
- iOS still matters as a *browser*: the PWA is installed on iPhones via Safari, so keep iOS-Safari quirks (keyboard inset, safe areas, push permission rules) working.

## Commands

- `npm install`, then `npm run web` (`expo start --web`) for day-to-day work.
- `npm run build:web` (`expo export -p web`) builds the PWA into `dist/`. With no linter or tests, this is the quickest correctness check (it fails on syntax/import errors).
- Deploy: the Vercel project `vgrand-task-hub` auto-builds `main` using `vercel.json` (`npm run build:web` → `dist`, SPA rewrite to `index.html`). Add the hosting origin to the backend's `CLIENT_URL` (comma-separated CORS/Socket.IO allowlist).

## Environment

- Only `EXPO_PUBLIC_*` vars belong in `.env`, and they are inlined at build time, so a Vercel/EAS rebuild is needed after changing any. On Vercel set them on the `vgrand-task-hub` project (the `VITE_*` vars left there are unused).
- `src/config/index.js` reads `EXPO_PUBLIC_API_URL`, `EXPO_PUBLIC_SOCKET_URL`, `EXPO_PUBLIC_FIREBASE_*` and `EXPO_PUBLIC_GOOGLE_TRANSLATE_API_KEY`. There is no production default: a missing `EXPO_PUBLIC_API_URL` falls back to `http://localhost:5000/api` with a console warning. (The comment in `.env.example` claiming a Render default is stale; the backend now runs on Railway.)

## Architecture

- Entry: `index.js` → `src/App.jsx`: `ThemeProvider` › `AuthProvider` › `ChatProvider` › `TodoProvider` › `NotificationProvider` › `LanguageProvider` › `ErrorBoundary` around `src/navigation/AppNavigator.jsx`, plus global `ToastHost` and `DialogHost`. Tabs: Home, To-do, Chat, More (business tasks live in the To-do screen, there is no Tasks tab); every other screen is on the native stack. In a wide browser window (>= 1024px, `hooks/useBreakpoint.js`) the tab bar is replaced by the persistent `components/AppSidebar.jsx` and single-column screens are centred by `framed()` in `AppNavigator.jsx`; phones keep the tab bar. Users with `must_change_password` only see `ChangePassword`. `navigationRef.js` exposes `openNotificationTarget(data)` for deep links and push taps.
- **API client** (`src/api/client.js`) is the single axios instance: attaches the JWT, clears credentials on 401, silently retries GETs twice on network errors/timeouts/502-504, and shows a throttled "Connection problem" toast for failed user-initiated requests. It never navigates to an error page. Pass `__skipOops: true` in the request config for background calls to suppress the toast. `ErrorBoundary` self-resets after 250ms (up to 3 times in 10s) before showing its manual "Try Again" fallback. The `Oops` cat screen is still registered but nothing navigates to it any more.
- **Realtime:** `src/context/ChatContext.jsx` owns the Socket.IO connection and exposes `subscribe(event, handler)` for `todo:changed` and `notification:new`. `TodoContext` (optimistic to-dos with undo) and `NotificationContext` (badges, in-app banners, push permission) build on it. The socket event contract and chat REST endpoints are documented in the backend README; keep it and `ChatContext.jsx` in sync.
- **Push:** the live path is `notifications.web.js` → `webPush.web.js` (Firebase Messaging, web/PWA); the Expo-based `src/services/notifications.js` is native-only legacy. `public/sw.js` is the service worker (network-first shell cache; skips `/api` and `/socket.io`; handles `push` / `notificationclick`; cache name `taskhub-shell-vN`). Keep Firebase imports in `*.web.js` files so native bundles don't pull them in.
- **Platform splits** use the `.web.js` suffix, and Metro resolves the web file on web: `src/utils/secureStorage.js` re-exports `expo-secure-store` (native legacy), while `secureStorage.web.js` uses `localStorage`. Import `secureStorage` rather than `expo-secure-store` directly, and put any new platform-specific behaviour in the `.web.js` file.
- **Web UX quirks:** `Alert.alert` is routed to the themed `DialogHost` on web (react-native-web's is a no-op), so prefer `showToast` / `showDialog` / `confirmDialog` from `src/utils/events.js` in new code. Bottom sheets that contain inputs use `<BottomSheet avoidKeyboard>` (iOS PWA keyboard inset via `useKeyboardInset`). Pushed stack screens need their own back button (`BackTitle` / `IconButton`) because the installed PWA has no browser back.
- **Permissions come from the server:** `todo.permissions` flags (`can_edit`, `can_approve`, `can_review`, `can_request_delete`, …) decide which actions the UI shows; don't re-derive them client-side. Roles are `user` / `admin` / `super_admin`. People and business management live only in `OrganizationScreen` (the old Businesses / Users / User Passwords screens are gone).
- **Shared data:** `src/hooks/useDirectory.js` is the 2-minute-cached org directory (`/org/directory`) used by @mention and person pickers; reuse it instead of fetching users per screen. Shared UI primitives live in `src/components/` (`kit.jsx` has Avatar, Chip, DueChip, TodoCheckbox, Fab, ProgressRing and colour/priority helpers).
- **To-do timeline & Team Monitor:** `src/utils/timeline.js` holds statuses (`todo`, `in_progress`, `blocked`, `in_review`, `on_hold`, `done`), blocker kinds, durations and `todoHealth()` (a mirror of the backend's `src/utils/timeline.js`: keep both in step; the backend one has the unit tests). `TodoTimeline.jsx` (status, accountable assignee, blockers, "post update", numbers, history) lives in the to-do detail sheet; `TimeHealth.jsx` has the shared pieces (`HealthPill`, `HealthBanner`, `MetricsGrid`, `TimelineEntries`, `useNowTick`). `TeamMonitorScreen` / `PersonMonitorScreen` / `MonitorTodoSheet` are for `user.can_monitor` (Chairman, Chief of Staff, Directors, business heads): they see people strictly below them and can "Ask why" (a `todo_comments` row with `kind = 'question'`). To-do UI building blocks: `QuickAddSheet` (`+label`, `for 2h`, `{deadline}`, tap a mention to assign; a Personal / business chooser, and a member's business task becomes a proposal), `FiltersSheet`, `BoardView`, `BulkBar`, `ProductivitySheet`, `useWebReorder` (desktop drag-and-drop ordering).
- **One module for personal to-dos and business tasks.** `screens/TodosScreen.jsx` shows the person's own work (Today / Upcoming / Inbox / Shared / Completed / lists / filters / labels) and one view per business (`biz:<id>`), each in four layouts: list (grouped by due date; finished items stay struck out on their date with "Completed by ..."), Kanban board (`BoardView`: a list or the Inbox is one column per section, a business groups by status / person / priority, other personal views group by status; drag between columns on desktop, a move button on touch, order saved per viewer through `saveBoardOrder`), month calendar (`CalendarView`, every to-do on its date, finished ones struck out; a deadline on another day also appears on its own day). The person picks the layout and it is remembered on the device (`todos.layout` in `secureStorage`); a view that cannot show it falls back to the list without forgetting it. A deadline that is overdue, today or within 2 days (`deadlineState()` in `utils/todoMeta.js`) is red in the list, board and calendar and a Gantt-style timeline (`TimelineChart`, loaded from `GET /api/todos/gantt`). Rows come from `TodoTreeList` + `TodoItem` (sub-tasks at any depth via `buildTree` in `utils/todoMeta.js`). The detail view is `TodoDetailSheet.jsx`: **a window in the middle of the screen** on every width (full height on a phone), never a side panel. Left: the title with its description directly under it (one block), the progress bar and percentage, the sub-tasks, then Comments / Activity (`TodoComments` has attach, emoji and mic; the mic uses `useVoiceInput` + `VoiceLive`); right: where it lives, status, date, repeat, deadline, priority, labels, reminder (date, time, daily/weekly/monthly, "before it is due"), time needed and people. The three dots hold share, duplicate, move to business, template, print (`utils/printTodo.js`), thank and delete, and the (i) shows who made it and when. A to-do with no date is not on Today: quick add no longer defaults the date; a creator can "Move to business" on a personal to-do; a to-do with no date and no deadline just stays open and shows how long it has been open; business controls (accept / decline a proposal, approve / ask for changes, warn, ask to delete) are `GovernancePanel`, and all of it follows `todo.permissions`. Phones use a segmented "My to-dos / Business" switch; desktop uses `WorkSidebar`. Approvals (`ApprovalsScreen`) lists proposals, finished work and delete requests waiting on the person.
- **Where a new to-do goes.** Nothing pre-fills a date (not quick add, Home, My Day or the global "Add task"): a to-do without a typed or picked date lands in the **Inbox** (or its list), never on Today, and the toast says where it went. The To-do screen opens on the Inbox unless `preferences.defaultView` says otherwise. In the Inbox, personal to-dos come first (with the Inbox's sections) and business work given to me sits in its own group per business; business rows carry a solid red `bizBadge` in `TodoItem`. @mentions in titles are drawn by `MentionText` / `splitMentions` (`kit.jsx`, no regex lookbehind: older iPhone Safari cannot parse it).
- **Assigned vs shared, @people and @me, sections, favourites.** `isAssignedTodo` / `isSharedTodo` (`utils/todoMeta.js`) split the two: assigned = someone other than the creator is accountable, shared = several people and nobody singled out. In quick add (`peopleFields` in `QuickAddSheet`): **@people without @me** hand the to-do to them and keep it off my list (one person: `delegate_to`, accountable; several: `delegate_ids`, shared between them); **with @me** (`parseQuickAdd` sets `me` and strips it from the title; my own @username counts too) it is on my list and theirs: one other person is assigned by default and the chip toggles to shared, several are shared by default (`assignId`: null default, -1 shared). Tagged real people (and @me) get a red tint behind them while typing: a transparent mirror `Text` under the transparent textarea (`inputShadow`, same font metrics; keep them in step). **Sections follow the tick:** a place's section named Completed / Done / Finished (`doneSectionOf`) receives a to-do when it is ticked, and reopening one from there moves it to Ongoing / In progress / To do (`activeSectionOf`) or "No section" (`followSection` in `TodoContext`, top-level items only; `toggleTodo(t, { keepSection: true })` skips it). Dropping a board card on that column ticks it, dragging it out reopens it; the list view shows finished items inside that section. "Start with 3 sections" creates To do / Ongoing / Completed. Sections (Inbox and lists) show "No section" first, an "Add section" line (`AddSectionLine`) between sections that inserts at that place, a description under the title and a three-dots `SectionMenu` (edit, move earlier/later, duplicate, move to business, archive, delete); archived sections are hidden behind "Archived sections"; `SectionEditorSheet` edits name + description; "Start with 3 sections" creates ordinary ones. Lists, filters and labels have a three-dots `ItemMenu` (favourite, edit/rename, duplicate, move to business, delete) and favourites show in the sidebar (`favorites`, `toggleFavorite` in `TodoContext`).
- **Business views have the same tools.** `biz:<id>` has a bar (`bizBar` in `TodosScreen`): list grouped by Date or by Section, "Show" chips that narrow it by a built-in or saved filter or a label (`bizFilter` → `bizTodos`, which keeps a task's sub-tasks with it), new filter, archived sections; the board can group by Section (columns are the business's sections, dropping a card sets `business_section_id`). Section tools are the same components (`SectionMenu`, `SectionEditorSheet`, `AddSectionLine`), shown only when `business.can_manage`. **Dragging sections:** list sections by their title (`hooks/useSectionReorder.js`: wrappers carry `data-section-id`, the "No section" group `data-section-top`), board columns by their title (own listener in `BoardView`, `data-col-section` / `data-col-handle`); both call `reorderSections(ids)` with every section id in the new order and are verified to send the right order. Touch uses Move earlier / later in the menu.
- **Leaderboard, Access, Everything.** `LeaderboardScreen` (everyone), `AccessScreen` ("Who can do what": a switch per module per person, `user.permissions.manage_access`) and `EverythingScreen` (read-only look at anyone's to-dos and every chat, `view_all_todos` / `chat_audit`) are stack screens linked from the sidebar and the phone More menu; gate any new UI on `user.permissions.<key>` (from `/auth/me`), never on a role. The Organisation screen shows one "Leadership circle" without role names, and "Add people" selects several people (or Everyone) for a business.
- **Voice and reminders.** `utils/speech.js` keeps listening through pauses (restarts on Chrome's early end, keeps earlier words); `hooks/useVoiceInput.js` wraps it and `components/VoiceLive.jsx` shows the wave and the transcript typing in. A `todo_reminder` notification plays the distinct bell `playReminder()` (`utils/feedback.js`, preference `reminderSound`, default on) and the service worker keeps the system notification on screen.
- **Desktop keyboard shortcuts are user-editable.** Every shortcut is an action id in `utils/shortcutRegistry.js` (`ACTIONS`: id, group, label, `scope`, default combos); screens bind handlers by id with `useShortcuts({ 'todo.quickAdd': fn }, enabled)` and never by raw key (only the literal `Escape` is allowed). A combo is chords separated by a space (`g t`), a chord is modifiers + key (`alt+space`, `mod+shift+k`; `mod` = Ctrl or Cmd). One document listener (the dispatcher in the registry) serves every `useShortcuts` call, with a single pending-sequence state. People rebind in `ShortcutsSheet` (opened with `?`, the sidebar or Ctrl+K): any key, modifiers, sequences of up to three, several combos per action, per-action and global reset; overrides live in `secureStorage` under `shortcuts.custom`. `findClash` blocks two actions that can be live together (scopes `global`, `todos`, `calendar`, `chat`, `approvals`; todos and calendar overlap) from sharing a combo or one being the prefix of another, and offers to replace. Hints in menus come from `useHint()` / `hintText(id)`. Adding a shortcut = add it to `ACTIONS`, bind the id, done (the help window lists it automatically).

- **Surfaces (flat, light and dark; Liquid Glass was removed in the revamp).** Every surface is a flat CSS panel in `public/index.html`, selected by `data-glass="<variant>"` (the attribute name is historical; spread `{...glass('card')}` from `src/theme/glass.js`): `bar` (sidebars, headers), `card`, `sheet` (dialogs, sheets, palette), `capsule` (floating input bar, tab bar, toasts), `button`, `accent` / `accent-deep` (the blue primary action), `tint` (the selected entry), `menu`, `inset` (a tile inside a panel) and `scrim`. Opaque surface, hairline border, soft shadow, no blur. Light / dark come from `html[data-theme]` (set by `ThemeProvider`), which also paints `colors.page`. The CSS wins over RN backgrounds (`!important`). Text on `accent` must be `'#fff'`, not `colors.white` (a dark surface in dark mode).
- **Springs.** `src/theme/motion.js`: `apple(response, ratio)` and the `SPRING` set (smooth, sheet, press, release, pop, momentum, layout), plus `project()` (where a flick lands) and `rubberband()`. `AnimatedPressable` is a liquid squish (spring press, bouncy release, small corners tighten); `TodoItem` swipes rest open on glass action buttons and hand the release velocity to the spring; `TodoTreeList` springs newly added rows in, removed rows out and neighbours into place; `BottomSheet` / `Modal` / `DialogHost` materialise with scale + fade and take the drag velocity on release; `InlineQuickAdd` is the floating glass capsule at the bottom of the To-do screen (the old FAB and the top inline box are gone). Reduced motion falls back to short fades. The SF-like type ramp is `type` in `theme.js`.
- **Module motion and panels.** The native stack does no transitions in a browser, so every screen is wrapped by `withScreenTransition` (`components/Reveal.jsx`) and layout / view changes in the To-do screen replay a `Reveal`. Both play through the Web Animations API (compositor, keeps moving while JS renders) with the spring turned into a CSS `linear()` easing by `springCss()` in `theme/motion.js`, started in a layout effect; the wrapped screen is `memo`'d so focus changes never re-render it. Tabs never opened are mounted hidden on idle after start-up (`warm` + per-tab `lazy` in `MainTabs`, as a transition), and the phone tab bar switches on press-in. Every selected-state (layout switch, scope switch, mobile view tabs, chat tabs, sidebar entries, the mobile tab island) is one light-red highlight drawn by `SlideGroup` / `SlideItem` (`components/SlideGroup.jsx`, `data-glass="tint"`) that slides to the active item, its leading edge running ahead of the trailing one; mark an item with `<SlideItem active>` inside a `<SlideGroup>` and give the control no background of its own. `BottomSheet` takes an `origin` rect: the capsule gathers into a bubble, flies to the middle of the screen and unfolds into the dialog (Quick add), and plays backwards on close; it measures its content height from the DOM, not `onLayout`. Controls ripple like water on press (`utils/water.js`, the shared `#th-water` SVG filter in `public/index.html`; automatic for glass controls, `water` prop otherwise). `Panel.jsx` (`usePanel`, `Panel`) makes the lists panel and the chat list collapse like drawers, toggled by a button in each module header; the main sidebar narrows to an icon rail (its Collapse entry, `mod+b`). Choices persist per device. Worklets must read shared values, never React state (closures go stale). `AnimatedPressable` holds a press 120 ms minimum so a quick click is felt. Reanimated follows the OS "reduce motion" flag by default (many Windows laptops have animation effects off, which made every spring an instant jump on desktop), so `App.jsx` sets `ReducedMotionConfig` to the app's own preference only, and `hooks/useReducedMotion.js` replaces Reanimated's hook. Quick add on a phone is a floating dialog centred in the space above the keyboard (animated `kb` padding), never bottom-anchored. Phones get a lighter blur (`@media (pointer: coarse)` in `index.html`), no scale in screen arrivals, and a cheaper, shorter water ripple that skips big panes.

- **Business workspace (inside the To-do screen).** Choosing a business shows tabs (`components/biz/BizTabs.jsx`): **Work** (the existing list / board / calendar / timeline, with one sprint line above it, `SprintStrip`, and "All work / This sprint / Backlog / Filters"; the old group-by and saved-filter rows are behind the Filters toggle), **Sprint** (`SprintTab`: plan, start, finish, "Is it too much?" capacity against velocity, who carries how much with a hand-over button, burndown, sprint tasks, backlog), **Epics**, **Releases** (`EpicsTab`, `ReleasesTab`, edited in `WorkItemSheet`), **Time** (`TimeTab`: running timer, week timesheet, approve / reject for managers; `TimeLogSheet`) and **Reports** (`ReportsTab` with `charts.jsx`: all bars in shades of the one red, no emojis). `TodosScreen` owns `bizTab`, `bizFilter` (kinds `filter`, `label`, `sprint`, `epic`, `release`) and shows a timer pill in its header; `inTab` (a tab other than Work) replaces the list and hides the layout switch and composer. In a task window two rows replace many fields: **Plan** (type, points, sprint, epic, release in one summary, edited in `PlanSheet`, also used for bulk "Plan" in the bulk bar, where only what you touch changes and "Give to" hands the tasks over) and **Time** (`TimeBox`). The board shows a column's WIP limit (`3 / 5`, red and "Too many" when over; managers set limits in `WipSheet` from the board toolbar), and cards show type and points. Shared state lives in hooks: `useWorkspace` (epics, releases, limits; one shared store), `useSprintList` / `useSprintDetail`, `useTimer` (one store for the running timer). Wording is plain on purpose: "Points", "Backlog", "Too much", "Start to finish"; never "velocity" or "burndown" as labels.
